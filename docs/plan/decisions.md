# Product-Owner Decisions

Answers to the questions in [open-questions.md](open-questions.md). A decision here overrides the question's suggested default. Affected tickets must follow it.

| ID | Decision | Date |
|---|---|---|
| Q-01 (part 1) | **Self-hosted open-source product.** Organizations install and run opportuniTY in their own environment. It is **not** offered as a hosted/cloud service by the project. One installation serves one organization with many workspaces; workspace isolation boundaries remain mandatory. | 2026-10-02 |
| Q-01 (part 2) | **Lite = evaluation/development only.** Lite keeps simple defaults and its docs state it must not hold real client data. **Full is the only supported production profile**: TLS between all components, PostgreSQL RLS, OpenSearch security plugin, sandboxed render workers and malware scanning on by default. | 2026-10-02 |
| Q-03 | **No dedicated benchmark hardware for now.** The 1M comparative spike (ADR-004, §27 PostgreSQL coding spike) runs on available developer hardware, with every hardware/version/setting recorded per §29. Because the hardware is not a frozen reference, gates are judged on *relative* measures (degradation vs. idle baseline on the same machine, correctness/security gates); absolute latency numbers are informational only. **10M validation (milestone M4) is postponed until a sponsor provides hardware.** Benchmark infrastructure must remain scripted so it can move to rented or sponsored hardware later. | 2026-10-02 |
| Q-07 | **Bulk jobs skip documents edited after the job started.** For each field a bulk job writes, a document whose value for that field was changed by anyone else after the job's start/snapshot point is left unchanged. The skip is recorded in coding history and in the job result. On completion the job reports a skipped count and a downloadable list of skipped documents for admin follow-up. Implementation: compare per-document (or per-field) version/last-modified at chunk execution against the job's start watermark. | 2026-10-02 |
| Q-08 | **Productions are exactly reproducible as of their original run.** A production records a frozen specification: materialized document-set snapshot, Bates assignments, production settings, and the versions of redactions, coding (endorsements/privilege handling) and field values used. Redactions and relevant coding are versioned (append-only) so those versions can be re-read later. A re-run regenerates output that matches the original page-for-page, verified against the stored manifest checksums. Output files may still be archived, but reproducibility must not depend on them. | 2026-10-02 |
| Q-12 | **Stale search hits show nothing.** Snippets, highlights, metadata columns and control numbers are protected content. Before any page of search results is returned, the API re-checks every hit on that page against authoritative PostgreSQL security state and drops hits the user may no longer see. Result counts and facets may be slightly approximate during the projection lag and the UI must say so. The post-filter cost (per page, not per result set) is measured in the ADR-004 spike. | 2026-10-02 |
| Q-20 | **MVP privilege log = metadata-only, auto-generated, with an optional per-document description.** One row per withheld/redacted-for-privilege document, populated from metadata (date, from/to/cc/bcc, subject/filename, custodian) plus privilege basis from coding (attorney-client, work product, etc.). Reviewers may add or override a description per document. Exports CSV/XLSX. Categorical logs are deferred (P2). | 2026-10-02 |
| Q-04 | **Benchmark gates are approved by the product owner and lead architect before the comparative run and may afterwards only be tightened, never relaxed.** Numeric definitions adopted: *material advantage* = ≥ 20% p95 improvement on gated query classes or ≥ 1.5× bulk throughput, consistent across all repetitions; *material failure at 10M* = any missed §26 gate, > 50% p95 growth from 1M to 10M, or a super-linear disk/merge trend. Degradation gates run at the calibrated maximum rate of the weakest candidate; ≥ 10K docs/s is measured separately as a ceiling. Per Q-03, gates are evaluated on relative measures on the same hardware. | 2026-10-02 |
| Q-09 | **MVP honours upstream dedupe and labels duplicates without suppressing them.** Import maps upstream duplicate group IDs and AllCustodians when present. Optional computed grouping is family-level, global scope, using the upstream dedupe/email hash when present, otherwise SHA-256 of the native. Duplicates are labelled and linked in the grid and viewer; nothing is hidden or auto-coded. Review suppression and propagate-to-duplicates coding are deferred (P2). | 2026-10-02 |
| Q-14 | **No automatic family inheritance of coding or privilege.** "Apply to family" is an explicit reviewer action with a conflict preview; families above 1,000 documents run as a bulk job (subject to the Q-07 skip rule). Production QC flags inconsistent families (e.g., privileged/withheld parent with produced children) before a production can be finalized. | 2026-10-02 |
| Q-11 | **Document-level restrictions are in MVP scope (M3).** Security-affecting fields: privilege status, confidentiality designation (e.g., Confidential / Attorneys' Eyes Only) and ethical-wall membership. Workspace admins configure which roles may see each restricted class. Restricted documents are invisible to unauthorized users everywhere, including search hits (per Q-12). Field-level restrictions are deferred (P2). | 2026-10-02 |
| Q-13 | **Full ethical walls.** Walls apply to individual users and to IdP groups (e.g., AD/Entra). Walled documents are hidden entirely from affected users, including search hits, counts and facets. Workspace admins can be walled. Emergency access uses a separate break-glass role whose every use is separately audited and reportable. | 2026-10-02 |
| Q-10 | **Stale counts are acceptable with a visible freshness banner and "≈" labels.** Privilege-review and production workflows offer an optional "wait until index is current" before running. Security-projection lag SLO: ≤ 5 s p95 after privilege/confidentiality/wall changes (access itself is enforced immediately per Q-12). Raw generation/watermark numbers are shown only to admins and support; reviewers see plain-language freshness ("current as of …"). | 2026-10-02 |
| Q-15 | **Exports re-check access at execution time and exclude denied documents with a report.** Each export chunk re-authorizes every document against current PostgreSQL security state (§24). Documents the requester can no longer access are excluded; the job result lists each excluded document and the reason, and the exclusion is audited. The export manifest reflects actual contents. | 2026-10-02 |
